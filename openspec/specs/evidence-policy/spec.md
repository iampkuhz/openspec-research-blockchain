# 证据政策

## 目的

定义本仓库所有研究工作的长期证据要求。

## 要求

- 技术主张优先依赖 `L1` 或 `L2` 证据。
- 必须区分协议原生能力、官方生态能力、第三方能力。
- 必须区分已上线能力、规划中能力、宣传性表述。
- 必须显式记录 `` `evidence-gap` `` 与 `unresolved ambiguity`。
- `decision` 输出必须继承这些证据约束，不得绕开。

## 证据等级定义

| 等级 | 来源类型 | 说明 |
|------|----------|------|
| L1 | 官方规范文档、EIP/RFC、白皮书、参考实现代码 | 最高权威性 |
| L2 | 官方文档、技术文档、Release notes | 高权威性 |
| L3 | 官方博客、公告、生态项目文档 | 中等权威性 |
| L4 | 第三方分析、社区讨论、媒体文章 | 参考性质 |

## 验证状态标记

| 状态 | 说明 | 处理方式 |
|------|------|----------|
| `[已验证]` | 链接可通过工具访问且内容匹配 | 直接使用 |
| `[未验证] 安全策略拦截` | 因企业安全策略无法访问（claude.ai blocking） | 记录证据缺口，使用替代来源 |
| `[未验证] URL 失效` | 链接返回 404 或重定向到无关页面 | 尝试 Wayback Machine 或记录缺口 |
| `[未验证] 需要认证` | 需要登录或特殊权限才能访问 | 记录缺口，或寻找公开替代来源 |
| `[未验证] 内容不匹配` | 链接可访问但内容与描述不符 | 降低证据等级，标注 discrepancy |

## 安全策略拦截处理

当首选 MCP 不可用、且回退到 `WebFetch` 后返回 "Unable to verify if domain is safe to fetch" 时：

1. **不得**重复尝试相同域名
2. **必须**在来源规划中标注 `[未验证] 安全策略拦截`
3. **优先**回到 `fastmcp-gateway` 的 `searxng_search_web`；若不可用，再使用 WebSearch 获取第三方来源（Mirror、Medium、GitHub 等）
4. **记录**证据缺口在 `draft.md` 的"证据缺口"章节
5. **标注**相关结论的置信度为"基于已有知识，待 L1 验证"

执行层应在 Harness 中把上述正式政策落实为来源验证、证据映射和回修流程。
