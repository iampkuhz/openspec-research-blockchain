# 比较分析写作规则

## 目的

规范 comparison note 的写作结构和内容要求。

## Comparison Note 结构

```markdown
# 比较概述

[比较的对象、维度、目的]

## 比较维度

### 维度 1: [名称]

[为什么选择这个维度]

| 对象 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 描述 | ... | ... | ... |
| 优势 | ... | ... | ... |
| 劣势 | ... | ... | ... |

### 维度 2: [名称]

...

## 综合对比

[跨维度的综合对比]

## 适用场景

| 场景 | 推荐方案 | 理由 |
|------|----------|------|
| ... | ... | ... |

## 不适用场景

[每个方案的局限性]

## 证据等级

[每个主张的证据来源]
```

## 写作要求

### 必须明确比较目的

**禁止**为比较而比较。

**必须**说明：
- 为什么比较这几个对象
- 服务于什么决策
- 目标读者是谁

### 必须使用固定维度

**禁止**随意切换维度。

**推荐维度**：
| 维度 | 描述 |
|------|------|
| 技术机制 | 核心实现方式 |
| 安全性 | 安全假设和风险 |
| 性能 | Gas 成本、延迟 |
| 生态成熟度 | 采用率、工具支持 |
| 兼容性 | 与现有系统集成 |

### 必须有证据支撑

**禁止**主观判断。

**必须**：
- 每个 `claim` 绑定 `evidence` level
- 区分事实和观点
- 说明数据来源

## 质量检查清单

- [ ] 比较目的是否明确
- [ ] 维度是否固定
- [ ] 是否有证据支撑
- [ ] 是否区分事实和观点
- [ ] 是否有适用场景
- [ ] 是否有不适用场景
- [ ] 证据等级是否标注
