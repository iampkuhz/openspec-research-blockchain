# 演进分析写作规则

## 目的

规范 synthesis/evolution 类型分析的写作结构和内容要求。

## Evolution Atom 结构

```markdown
# 演进概述

[演进的时间范围、关键里程碑]

## 演进阶段

### 阶段 1: [名称]

- 时间范围
- 关键事件
- 主要变化
- 驱动因素

### 阶段 2: [名称]

...

## 演进驱动因素

### 技术驱动

- ...

### 生态驱动

- ...

### 问题驱动

- ...

## 不变的原则

[演进过程中保持不变的核心设计原则]

## 关键分歧点

[曾经讨论但最终未采用的方向]

## 当前状态

[最新状态，待决问题]
```

## 写作要求

### 必须按时间线组织

**禁止**跳跃式叙述。

**必须**：
- 明确时间范围
- 标注关键日期
- 按因果顺序组织

### 必须区分变化类型

| 类型 | 描述 | 示例 |
|------|------|------|
| Breaking | 破坏兼容性 | EIP 版本升级 |
| Additive | 新增功能 | 新增 opcode |
| Clarification | 澄清说明 | 补充文档 |
| Optimization | 优化 | Gas 优化 |

### 必须说明驱动因素

**禁止**只描述"发生了什么"。

**必须**解释：
- 为什么发生这个变化
- 什么问题驱动
- 谁推动的

## 质量检查清单

- [ ] 时间线是否清晰
- [ ] 是否区分变化类型
- [ ] 是否说明驱动因素
- [ ] 是否列出关键分歧点
- [ ] 是否说明不变原则
- [ ] 当前状态是否更新
