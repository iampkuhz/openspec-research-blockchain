# 定义原子写作规则

## 目的

规范 definition atom 的写作结构和内容要求。

## Definition Atom 结构

```markdown
# 定义

[1-2 句简洁定义，包含核心本质]

## 形式化描述

[可选：伪代码、类型签名、接口定义]

## 关键术语

| 术语 | 定义 | 来源 |
|------|------|------|
| <术语 1> | <简洁定义> | <source id> |
| <术语 2> | <简洁定义> | <source id> |

[可选：补充说明]
- 针对特定术语的额外说明
- 术语之间的关系
- 使用注意事项

## 边界条件

### 包含的内容
- ...

### 不包含的内容
- ...

## 前提条件

[理解此定义需要的前置知识]

## 相关概念

[与哪些概念相关，如何区分]
```

## 写作要求

### 定义必须

1. **简洁**：1-2 句表达核心
2. **准确**：使用 L1/L2 证据
3. **有边界**：明确 excludes
4. **可引用**：其他 `atom` 可引用此定义

### 术语区必须

1. **使用表格**：术语、定义、来源三列
2. **标注来源**：每个术语绑定 `source`
3. **补充说明**：针对需要额外说明的术语，可在表格下方用列表补充

### 边界必须

1. **写清楚不是什么**：排除常见误解
2. **说明适用范围**：何时使用此定义

### 图表要求（默认从简）

`definition atom` 的目标是给出准确边界，不要求强制交付 primitive 那套"四视图"。

默认做法：
- 优先使用术语表、边界列表、相关概念对比表
- 只有在纯文字难以区分概念时，才补一个小型关系草图或概念对比表

**禁止**：
- 为了"看起来完整"而机械补角色边界图、组件图、状态图
- 把 mechanism 级细节塞进 definition atom

**允许的轻量可视化**：
- Markdown 表格
- Mermaid 简单关系图
- ASCII 概念草图

## 质量检查清单

- [ ] 定义是否简洁准确
- [ ] 是否覆盖所有关键术语
- [ ] 边界是否清晰
- [ ] 前提条件是否列出
- [ ] 相关概念是否区分
- [ ] 所有术语是否有来源
- [ ] 是否避免误引入 mechanism 级完整图组
