# 结构规则

## 目的

规范知识文档的整体结构。

## 文档通用结构

```markdown
# 标题

[1-2 句概述]

## 概述

[高层介绍，3-5 段]

## 关键术语

[核心术语列表]

## 核心内容

[主要章节]

## 边界条件

[适用范围和限制]

## 参考

[相关链接和文档]
```

## 标题规范

### 必须

- 准确反映内容
- 使用技术术语
- 简洁（<50 字）

### 禁止

- 模糊标题（"分析"、"总结"）
- 营销语言
- 过度简写

## 概述规范

### 内容

1. **第一段**：定义/定位
2. **第二段**：核心作用
3. **第三段**：与其他主题关系

### 长度

- 3-5 段
- 每段 2-4 句
- 总长 200-400 字

## 章节组织

### 标准章节顺序

```
1. 概述
2. 关键术语
3. [核心内容章节]
4. 边界条件
5. 待决问题
6. 参考
```

### 章节标题层级

```markdown
# H1 - 文档标题
## H2 - 主要章节
### H3 - 子章节
#### H4 - 细节
```

**禁止**超过 H4。

## 段落规范

### 段落长度

- 2-6 句/段
- 过长则拆分
- 过短则合并

### 段落结构

```
主题句
↓
解释/展开
↓
示例/证据
↓
连接/过渡
```

## 列表使用

### 何时使用列表

- 并列项目
- 步骤序列
- 分类枚举

### 列表格式

```markdown
### 类型 1: 无序列表

- 项目 1
- 项目 2
- 项目 3

### 类型 2: 有序列表

1. 步骤 1
2. 步骤 2
3. 步骤 3

### 类型 3: 定义列表

**术语 1**
: 定义 1

**术语 2**
: 定义 2
```

### 列表深度

**禁止**超过 3 层嵌套。

```markdown
✅ 正确：
- 一级
  - 二级
    - 三级

❌ 错误：
- 一级
  - 二级
    - 三级
      - 四级（禁止）
```

## 术语使用

### 首次使用

**必须**：
- 全称 + 缩写
- 简洁定义
- 英文原文

```markdown
**UserOperation**（以下简称 UserOp）
: EIP-4337 定义的用户操作原子
```

### 后续使用

**一致**：
- 使用同一术语
- 不混用同义词

## 示例：完整结构

```markdown
# EIP-4337 定义

EIP-4337 是一个实现账户抽象的 ERC 标准，通过伪交易对象
UserOperation 和 EntryPoint 合约，允许用户在不修改协议层
的情况下实现智能合约账户。

## 概述

EIP-4337 由 Vitalik 等人于 2022 年 2 月提出，旨在解决以太坊
账户模型的限制。

核心思路是引入伪交易对象 UserOperation，由 Bundler 打包后
提交到单例合约 EntryPoint 处理。

与 EIP-2938 不同，EIP-4337 不修改协议层，而是在应用层实现
账户抽象，降低了实现复杂度和部署门槛。

## 关键术语

**UserOperation**
: 伪交易对象，包含用户意图的完整信息。

**EntryPoint**
: 单例合约，处理 UserOperation 的验证和执行。

**Bundler**
: 链下角色，打包 UserOperations 并提交。

**Paymaster**
: 可选的智能合约，代付 Gas 费用。

## 边界条件

### 适用范围

- ERC-4337 兼容的智能合约账户
- 支持签名的钱包

### 不适用范围

- L1 协议层账户抽象（见 EIP-2938）
- 账户恢复（需额外实现）

## 待决问题

- Gas 优化空间
- 跨链互操作性

## 参考

- [EIP-4337 规范](https://eips.ethereum.org/EIPS/eip-4337)
- [参考实现](https://github.com/eth-infinitism/account-abstraction)
```
