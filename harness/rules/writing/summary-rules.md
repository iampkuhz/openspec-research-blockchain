# 摘要规则

## 目的

规范文档摘要的写作方式。

## 摘要类型

### 类型 1: 章节摘要

**位置**：章节开头
**长度**：1-2 段
**用途**：预告章节内容

```markdown
## 核心机制

本节介绍 UserOperation 的处理流程，包括验证、执行、
Gas 计算三个核心环节。
```

### 类型 2: 文档摘要

**位置**：文档开头（概述后）
**长度**：3-5 句
**用途**：总结文档要点

```markdown
## 摘要

本文档定义 EIP-4337 的核心概念和机制。

关键内容：
- UserOperation 数据结构和语义
- Bundler/EntryPoint/Paymaster 角色
- 验证和执行流程
- Gas 计算模型
```

### 类型 3: 执行摘要

**位置**：长文档/报告开头
**长度**：200-300 字
**用途**：决策者快速理解

```markdown
# 执行摘要

## 背景
[为什么重要]

## 核心发现
[关键发现 1-3]

## 建议
[建议 1-3]
```

## 写作原则

### 原则 1: 独立可读

摘要应独立可读，不依赖正文。

**必须**：
- 完整的句子
- 清晰的表述
- 无未定义术语

### 原则 2: 覆盖要点

摘要应覆盖所有要点。

**检查**：
- [ ] 核心主题
- [ ] 关键发现
- [ ] 主要结论

### 原则 3: 简洁

摘要应简洁，不展开细节。

**禁止**：
- 详细数据
- 复杂推导
- 过多引用

## 摘要结构

### 标准结构

```
1. 背景/目的 (1 句)
2. 核心内容 (2-3 句)
3. 结论/建议 (1-2 句)
```

### 变体结构

**比较文档**：
```
1. 比较对象 (1 句)
2. 主要差异 (2 句)
3. 适用场景 (1 句)
```

**演进文档**：
```
1. 时间范围 (1 句)
2. 关键阶段 (2 句)
3. 当前状态 (1 句)
```

## 关键词选择

### 必须包含

- 核心主题词
- 关键术语
- 核心结论

### 避免包含

- 模糊词汇
- 条件句
- 未决问题

## 位置规范

### 文档级摘要

```markdown
# 标题

[概述：1-2 段]

## 摘要

[摘要内容]

---

[正文]
```

### 章节级摘要

```markdown
## 章节标题

[章节摘要：1-2 句]

### 子章节

[子章节内容]
```

### 长文档摘要

```markdown
# 标题

## 执行摘要

[完整摘要，200-300 字]

## 目录

...
```

## 长度指导

| 文档长度 | 摘要长度 |
|----------|----------|
| <1000 字 | 50-100 字 |
| 1000-3000 字 | 100-200 字 |
| 3000-5000 字 | 200-300 字 |
| >5000 字 | 300-500 字 |

## 示例

### 示例 1: Definition Atom 摘要

```markdown
# EIP-4337 定义

EIP-4337 是一个实现账户抽象的 ERC 标准。

## 摘要

EIP-4337 通过 UserOperation 伪交易和 EntryPoint 合约，
在应用层实现账户抽象。核心角色包括 Bundler、Paymaster、
Aggregator。与 EIP-2938 不同，不修改协议层。

[正文]
```

### 示例 2: Comparison Note 摘要

```markdown
# BFT 共识比较

## 摘要

对比 Tendermint、QBFT、Simplex、Malachite 四种 BFT 共识方案。
Tendermint 生态最成熟，Simplex 性能最优，Malachite 是新兴
方案。联盟链推荐 QBFT，公链推荐 Tendermint，高性能场景可
考虑 Malachite（风险较高）。

[正文]
```

### 示例 3: Evolution Atom 摘要

```markdown
# AA EIP 演进

## 摘要

AA EIP 从 2021 年 EIP-2938 发展至今，经历了协议层探索、
ERC 方案、方案分化三阶段。当前 EIP-4337 已主网上线，
EIP-7702 在规划中。演进驱动因素包括技术复杂性、生态需求、
Gas 优化。
```

## 检查清单

- [ ] 是否独立可读
- [ ] 是否覆盖要点
- [ ] 是否简洁
- [ ] 位置是否正确
- [ ] 长度是否合适
