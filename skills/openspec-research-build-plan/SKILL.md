# 生成研究计划

## 何时使用

- `request.md` 已经写好
- 需要把问题收紧为可执行计划
- 需要一次性生成预算、来源规划、evidence gap 与后续确认问题

## 输出要求

- `plan.md`
- 如确有必要，再补 `dependencies.md`、`decision-criteria.md`、`evidence-matrix.md`

## 强约束

- `plan.md` 是 review 文件，不是分析正文
- 把计划层与来源规划层的职责合并到 `plan.md`
- 对 `primitive`，把“为什么不改传统 transaction 路径”“角色分别位于哪一层”“哪些能力不是 protocol-native”这类问题写进“后续确认问题”
- 结论优先依赖 `L1/L2`
- 明确区分协议原生、官方生态、第三方能力
